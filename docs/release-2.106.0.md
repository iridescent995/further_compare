# Release 2.106.0 — folder imports into archives

Archive Edit and right-click menus now offer Add folder to left/right. The selected folder name, nested files and empty directories are preserved. Review every addition, folder merge and file overwrite before applying in memory. Matching directories merge without removing unrelated existing entries. Destination edits require a fresh review; undo and redo restore the complete archive contents. Save ZIP is a separate explicit action.

The native picker snapshots one folder tree, bounded to 5,000 entries, 32 MiB of file contents and 128 levels. Directory enumeration is bounded. Links and special files are rejected. Ancestor identity, file descriptors, file sizes/timestamps, directory listings and the selected root are checked to reject changed or replaced sources. Picker cancellation and stale session/window results leave the archive unchanged. Existing portable path, type, case collision and final ZIP size checks also apply.

Validation: 893 unit tests passed, with one Windows-native attribute test skipped. Source desktop tests passed exact binary and empty-file bytes, retained root and empty directories, folder merging, overwrite review, destination validation, cancellations, undo/redo, new archive creation, symlink rejection and unchanged source trees. Browser tests reject late folder-picker responses after reset or session replacement. Both review themes were visually inspected.

Both Apple Silicon and Intel Mac packages passed the complete recursive import workflow. Existing file-import, archive-save and context-menu keyboard regressions passed. All three package versions, UI and native bridge files matched the build. ZIP integrity, download links, sizes, SHA-256 and browser download checks passed. Shipped source contained no reference-product branding. Contained-file content editing, broader archive formats and metadata preservation, remote providers, Windows runtime validation and remaining full-product scope stay open.
