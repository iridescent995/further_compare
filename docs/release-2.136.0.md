# Release 2.136.0 — Ignored-text patterns

Text and normalized folder comparisons can ignore matches from up to 16 Unicode regular expressions, with independent case matching. Open **Ignored text…** in text options or folder Filters & options. Patterns match each original physical line; overlapping spans are combined independently of pattern order. Original content, line numbers and copied bytes remain intact. Ignoring all characters in a nonblank line does not erase that line or its final-newline significance.

Rules follow folder child comparisons, sessions, reusable defaults, swaps and reports. CLI text comparisons accept `--ignore-patterns JSON_FILE`; batch text jobs accept `ignoredTextPatterns`. Example JSON:

```json
[{"pattern":"timestamp=\\d+","matchCase":true}]
```

Pattern matching runs in protected workers. Browser comparisons and validation have five-second limits; selected-file reports have a twenty-second aggregate limit. Native workers have bounded concurrency and pending input, one-second execution limits, recovery, and filesystem revalidation after asynchronous processing. Invalid or timed-out patterns report errors rather than silently changing comparison semantics.

Browser checks cover overlapping patterns, invalid rules, original line structure, cancellation, actual comparison timeout, responsiveness and recovery. Native workflows cover closed-node exclusion, cache modes, inheritance, reports, saved sessions/defaults, swaps and original-byte copy. Existing report, live editor, blank-line and all eight whitespace-scope regressions pass. Light and dark dialogs were inspected.
