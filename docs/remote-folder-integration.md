# Remote folder integration

Current status: SFTP root selection, immediate-node comparison, file and paired-directory child sessions, manual reconnect, saved connection profiles and password/private-key authentication are packaged through 2.154.0 and verified on both Mac architectures. Remote selected-entry properties are packaged in 2.155.0 and verified on both Mac architectures; final archives and downloads pass integrity checks. SFTP text original-file saves are packaged in 2.156.0 and verified on both Mac architectures, including stale-content checks, exact encoding, retained child connections and background-comparison/open coordination. Actual Windows runtime remains unverified. Selected regular-file Copy is packaged in 2.157.0 and verified on both Mac architectures for local↔SFTP and SFTP↔SFTP, including review, backups, Stop and partial outcomes. Recursive transfers, other-format remote saves, persistent host trust, automatic related-tab recovery and remote session restoration remain unfinished. Earlier notes below describe historical incremental milestones; later release updates supersede their pending lists.

`LocalFolderMetadata` now supplies `FolderService.inspectRoot` and `inspectEntry`; `FolderTree` no longer reads the filesystem directly. Seven focused provider tests pass, including opaque endpoint identifiers, immediate-node access, stale request rejection and local replacement/link guards. Existing folder regression groups also pass. These source changes are not yet packaged.

The existing folder UI must retain immediate-node enumeration, in-place expansion, paired row identity, click selection and double-click child comparison for local/remote and remote/remote pairs. Remote support must extend that workflow, including reviewed transfers, rather than introduce a separate browser.

## Integration sequence

1. Move filesystem metadata and selected-root observations out of FolderTree into the folder service boundary. Keep the local implementation's canonical spelling, double observation, inode identity, ignored-path behavior and permanent rejection of replaced roots. Verify existing filename matching and alignment behavior as well as lazy browsing.
2. Generalize enumeration and bounded content reads. `desktop/folder-filename-inventory.cjs` now consumes streamed provider enumeration and metadata, with independent identity/stamp validation; `FolderService.listDirectoryPair` now also delegates immediate paired listing to the provider. Content comparison policy now uses provider readers; the concrete reader remains local until SFTP is implemented. Remote names use POSIX components independent of the host OS. A provider advertises supported operations; missing permissions or disconnected endpoints must become explicit errors, never equal or absent-file results.
3. Introduce a native SFTP connection registry with opaque endpoint handles. An endpoint observation includes connection generation, canonical remote root and server-provided metadata. SFTP servers do not universally provide inode or nanosecond timestamps: do not imply their metadata has local-filesystem identity guarantees. Transfer plans must revalidate available evidence and report limitations accurately.
4. Add explicit first-use host-key fingerprint review and persist the approved key binding to host and port. Changed keys are rejected pending new review. Credentials remain native and transient by default; saved profiles contain host, port, username and root only. Any credential persistence is an explicit choice using OS protection. Never store passwords in session files, renderer snapshots or logs.
5. Wire connection selection into existing left/right root controls and native menus. `desktop/window-runtime.cjs` owns current per-session FolderService and FolderTree authority; preserve those scopes and invalidate requests on reconnect, swap or session replacement.
6. Generalize `desktop/folder-pair.cjs`: stage both inputs fully before creating a child comparison, bound reads, revalidate both endpoints after reading, and retain opaque remote save authority separately from local disk tokens. Remote folder children inherit connection authority without serializing live handles.
7. Implement reviewed uploads/downloads and remote edit saves with progress, cancellation, temporary destination cleanup and negotiated server capabilities. Overwrite review must show exact source/destination, observed revisions and recovery behavior. Do not reuse local inode checks, rename guarantees or backup claims for a server lacking those capabilities.
8. Save endpoint descriptors in sessions, reconnect on restoration and obtain fresh authority. A stale or cancelled connection must leave the existing workspace intact.

## Required evidence before release

Use an isolated SSH/SFTP server and fixture keys to exercise local/remote and remote/remote pairs. Assert that opening one node lists and compares only that node; closed descendants remain unread. Test Unicode names, special characters, links, traversal rejection, host-key mismatch/change, authentication cancellation, disconnects, stale transfer plans, permission failures, bounded reads, cancelled temporary-file cleanup and reconnect/session restoration. Verify the existing local folder suite and actual packaged Mac/Windows workflows. A successful handshake alone is not a completed remote-folder feature.

## Transport API review

The transport dependency is pinned to `ssh2` 1.17.0. Installation scripts were disabled; optional-native-free Node loading succeeds. Its [official client documentation](https://github.com/mscdex/ssh2#client) supports asynchronous host-key verification. The adapter must always install an explicit verifier because omission accepts the server key automatically. Keep pending trust review tied to the connection attempt and close or reject it on cancellation; configure handshake timing deliberately so a late approval cannot revive an expired attempt.

For directory enumeration, use an SFTP directory handle and bounded batches, closing the handle on completion, cancellation or error. Avoid the convenience path-based `readdir` when it collects the whole directory. The [SFTP API](https://github.com/mscdex/ssh2/blob/master/SFTP.md) and actual installed implementation must be checked together, especially EOF handling. These APIs still require an isolated-server integration test before product use.

## Paired directory children after 2.150.0 (source verified)

Compare selected pair now stages remote/remote and mixed local/remote directory roots before creating a child folder comparison. It checks parent row authority and both metadata observations, then publishes through the native transaction queue. The context action is enabled for directories. Each child receives new opaque connection handles; native reference counting retains the transport when an idle parent closes. Explicit disconnect revokes only that owner’s providers and handles. No credentials or live handles are serialized.

The new actual Electron test covers nested children, mixed roots, distinct connection IDs, parent/child closure, explicit parent disconnect, invalid pairs, simultaneous-opening rejection and Stop during held metadata. Existing remote file-child and root-lifecycle tests pass. Seventeen registry unit tests and sixteen provider/registry integration tests pass. These changes are not packaged yet. Transport-level abort remains connection-wide, so cancellation of an active shared transport can require reconnecting related tabs; this does not imply independent SSH connections per tab. Remote saving, transfers and persistent reconnection remain unfinished.

Release update: paired directory children are now packaged in 2.151.0. Directory, dialog/context, file-child and root-lifecycle workflows pass on both Mac architectures. Archive/source/download checks pass for all three platforms. See `release-2.151.0.md`; actual Windows runtime and the remaining write/reconnect scope are still unfinished.

## Manual reconnect after 2.151.0 (source verified)

Existing remote roots now show Reconnect in the path row and Navigate context menu. The dialog prefills host, port, username and folder from the current endpoint, but never fills a password or reuses approval. Host-key review remains mandatory. Cancel preserves the current setup; successful attachment releases an unused displaced connection handle while preserving another root or retained child connection. The descriptor now carries the non-secret username for this purpose.

Browser prefill/reset/security checks pass. The actual desktop dialog test disconnects an endpoint and restores live comparison through Reconnect. Native replacement tests cover failed preparation, stale commit, shared opposite roots and retained child lifetime; folder/session regressions pass. Packaging remains pending. This is manual reconnect for the selected side, not automatic recovery of all related tabs or persistent connection profiles.

Manual reconnect release update: shipped in 2.152.0 and verified in both Mac packages, including incorrect-password preservation, disconnect/reconnect and retained-child lifetime. Archive, source/version and download checks pass for all three builds. Automatic related-tab recovery, persisted profiles, remote writes/transfers and actual Windows runtime remain outstanding.

## Saved profiles after 2.152.0 (source verified)

The connection dialog supports explicitly named profiles with select, save/update and delete controls. The native store saves only ID, name, host, port, username and folder; it rejects secrets and trust state. Host review and fresh authentication remain required. Profiles are limited to 100 and persisted through atomic replacement with serialized mutations across instances. Invalid or unsupported stores are reported without overwrite.

Twenty-three profile/registry unit tests pass. Browser tests cover allowed fields, password clearing, review lockout, stale loads/mutations and manual connection after list failure. Actual desktop tests verify persistence across restart, load/update/delete and no password on disk. The existing real SFTP dialog/reconnect flow also passes. A late connection cleanup bug that cleared a reopened dialog password is fixed and covered. The compact profile layout is visually inspected. Packaging and Windows runtime remain pending.

Saved profile release update: shipped in 2.153.0. Profile persistence/restart, actual connection dialog and remote directory workflows pass on both Mac packages. All three archive, bundled-source and download checks pass. Windows runtime and the remaining authentication, trust, automatic recovery and remote-write scope remain open.

## SSH key-file sign-in after 2.153.0 (source verified)

The connection dialog offers password or private-key authentication. Key selection uses the native picker and returns only an opaque ID and basename. Native reads are bounded to one MiB and require a regular file; key buffers remain session-owned, expire, and are cleared on use/discard/replacement/reset/disposal. A late picker result cannot create authority after session closure. Optional passphrases remain transient and explicit host-key approval is still required. Profiles store neither keys nor passphrases.

Twenty-eight key/profile/registry tests pass, along with browser key lifecycle and stale-dialog tests. A key-only fixture server verifies plain and encrypted-key authentication through real Electron IPC and the actual dialog. Both remote sides connect and show live equal file status. Existing password/session/reconnect workflows pass. Packaged Mac verification and actual Windows runtime remain pending.

Key-file authentication release update: shipped in 2.154.0. Plain/encrypted keys, profile restart, existing password/reconnect and session lifecycle tests pass in both Mac packages. All three archive, bundled-source and download checks pass. Actual Windows runtime, persistent host trust, automatic recovery and remote writes remain open.
