# Release 2.114.0 — explicit folder text encoding

Folder comparisons now offer a saved text decoding setting from the toolbar, context Compare menu and native Folder Comparison menu. Auto remains the default; UTF-8/16/32, Windows-1251/1252 and Latin-1 are supported. The setting applies to both sides for text comparison, child text sessions, selected file pairs and selected text reports. It does not rewrite files.

Normalized comparison caches include the encoding. Operation snapshots record and validate decoding provenance; filtered operations therefore use the same comparison semantics as displayed colors. Invalid text, binary content and files over the existing text limit retain exact-byte fallback. Child editors retain their decoded output format, and folder report exports identify the selected encoding.

Backend tests cover supported encodings, malformed/BOM/control fallback, alternating-cache invalidation, node and aligned comparisons, filtered-copy preview/application, explicit-encoding pairs and report contents. All 919 unit tests passed (one Windows-native test skipped). Source desktop checks passed cache/color changes, native/context/toolbar routes, node-only and selected refresh, child/pair decoding and inherited rules, selected-text and folder reports, saved sessions and tab isolation. Existing child rules, comparison controls and selection regressions also passed. Both Mac packages passed the complete workflow. Final style-only rebuilds passed native-menu/encoding and computed border/contrast checks in both architectures; actual dialog CSS was visually inspected in Chrome in light/dark themes because hidden Electron screenshots could not be captured. Paragraph contrast exceeds 4.5:1. Final package versions/UI/native files match source; ZIP integrity, downloads, sizes, SHA-256 and Windows ZIP browser download passed.
