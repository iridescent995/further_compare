# Next spreadsheet capability: ODS input for table comparison

Assessment: 2026-10-22, originally source at 2.199. This design has now been implemented and source-tested for 2.200; final release checks are recorded in `implementation-plan.json`. See `docs/ods-input.md` for the actual capability and limitations. The recommendations below remain design history, not evidence that every listed release gate or follow-on feature is complete.

## Recommendation

Implement **ODS workbook input with worksheet selection, cached-value comparison and ordinary result editing/export** next. A user should open an ODS beside XLSX/CSV, align by keys, review differences, copy selected values, undo, save/reopen the comparison, and export the result as CSV or a new XLSX. This removes an entire unsupported-input boundary across local, folder, remote and archive entry workflows. It is a defined first ODS milestone, not full ODS fidelity or completion of the remaining spreadsheet scope.

Do not begin another XLSX formatting increment first: it improves already-openable documents while ODS currently cannot enter the table workflow. XLS/XLSB remain subsequent input priorities; their binary containers/records would add a parser dependency or substantially more format work. These priorities are an engineering assessment, not measured user demand.

## Evidence and dependency choice

- `implementation-plan.json`'s current `spreadsheets` gap list explicitly retains XLS/XLSB/ODS. Use that current summary rather than historical milestone gap lists.
- `src/advanced.js` branches on `.xlsx` in `openSide`, `tableRows`, `tableHashes`/source identity, `setState`, result-template selection and source-preserving export. Other table inputs are decoded as UTF-8 delimited text. Adding an extension to a picker alone would therefore fail.
- `src/app.js:fileComparisonType`, `desktop/shell-requests.cjs:comparisonType`, folder/provider routing, archive eligibility, and `desktop/sessions.cjs` need explicit format decisions. Existing XLSX source-template and style/structure binding checks must retain their exact meaning.
- Installed runtime dependencies include ExcelJS 4.4, `@zip.js/zip.js` 2.24, XML DOM support and hashing; no XLS/XLSB/ODS reader is installed. ODS is a ZIP/XML package, so a bounded, namespace-aware cached-value reader can reuse existing package/XML primitives. No runtime office installation should be required. [OASIS package standard](https://docs.oasis-open.org/office/OpenDocument/v1.3/os/part2-packages/OpenDocument-v1.3-os-part2-packages.html).
- SheetJS is a credible alternative spanning all three formats, but its format list alone does not prove our limits, error behavior or interoperability. If prioritizing XLS/XLSB together later, first qualify its reader against independent files. Use a pinned, checksum-recorded official distribution: its documentation says the npm `xlsx` endpoint is stale. This plan does not install it. [Supported formats](https://docs.sheetjs.com/docs/miscellany/formats/), [official installation guidance](https://docs.sheetjs.com/docs/getting-started/installation/nodejs/).

## Implementation sequence

1. **Qualified ODS reader.** Add `src/ods-input.js` and a small format-dispatch/capability helper. Validate the ODS MIME/package manifest, required `content.xml`, namespace identities, duplicate/ambiguous entries and encryption declarations before interpreting cells. Reject DTD/external entity declarations; never execute scripts, resolve links, access remote data or calculate formulas. Enforce both advertised and actual ZIP expansion limits and XML work limits. Preserve the original input bytes unchanged.
2. **Explicit data semantics.** Read sheets, row/column repeats, covered cells and textual paragraphs/spaces/tabs with physical positions intact. Use typed stored values for numbers/booleans/dates/durations/currency, and text content for strings. Specify deterministic lexical conversion, including timezone-bearing dates and duration values; do not reinterpret them as Excel serial dates. ODS repeat attributes require bounded expansion before allocation. Skip trailing empty repetitions efficiently; reject nonempty logical extents above the existing row/column/cell limits. Preserve raw formula text plus its namespace as provenance; absent formula caches must be visible as unavailable, never equal to an ordinary blank. [OASIS schema: cells, values and repeated rows/columns](https://docs.oasis-open.org/office/OpenDocument/v1.3/OpenDocument-v1.3-part3-schema.html).
3. **Capability-aware table adapter.** Return the existing rows model plus an explicit `format:'ods'` and supported capabilities. Separate “workbook with sheets” from “preservable XLSX template”; avoid treating ODS as either delimited text or XLSX. Initially enable cached-value comparison, header/key matching, selected value copying, result editing/history, and value-only CSV/new-XLSX export. Keep formula-expression comparison, formatting/layout comparison, formula/style copy, structural workbook preservation and archive source writeback unavailable for ODS until their semantics are implemented. Explain this beside the input; do not silently compare empty style matrices or translate OpenFormula into Excel syntax.
4. **Routes and persistence.** Add ODS recognition to direct/table, folder pair/tree, shell, provider and archive-child routes. Reconstruct capabilities from original bytes on session restore. Extend source-kind validation where needed without weakening XLSX hash/template checks. A new value export must not overwrite the original ODS or a source inode alias; expose source-preserving save only for supported formats.

## Release gates and follow-on work

Use committed fixtures from LibreOffice and Excel-produced ODS, with independent readback; no local LibreOffice executable was found during this assessment. Cover multiple sheets, Unicode/rich text flattening, repeated/covered cells, merged positions, cached/missing formula results, dates/time/currency, empty versus absent cells, external-link data and malicious repetition/ZIP/XML inputs. Verify ODS↔XLSX/CSV keys, failed-load atomicity, tab/history/session restoration, direct/folder/remote/archive routing and value-only exports. Compare source hashes before/after. Run browser and both Mac packages; retain the explicit Windows runtime gap until exercised there.

Do not claim formula calculation, rendered-style equivalence or lossless ODS writing from a reader/export test. Follow with ODS formula namespace/reference semantics and preserving edits, then qualified XLS/XLSB readers; broader XLSX conditional/table/rich-text formatting, pivots and dynamic-spill evaluation remain separate tracked work.
