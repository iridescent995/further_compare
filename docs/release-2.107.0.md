# Release 2.107.0 — edit text entries inside archives

Text entries opened from an archive now have an Apply to archive action beside each editor’s Save control. Review the archive, entry path and encoded size, then update the open parent archive in memory without leaving the live text editor. Existing output encoding, BOM and line-ending settings apply. Wrap and the edited text tab remain intact. Archive undo/redo covers these updates; Save ZIP separately writes an archive to disk. Save as in the text editor still writes a standalone file.

Each child entry is bound to the exact archive inputs it was opened from. Applying rejects stale parent contents, missing sides, replaced editor sources and closed parents. The staged update validates complete output before publishing it to the inactive parent tab and preserves unrelated entries and the entry modification timestamp. Links are runtime-only, retained across tabs but omitted from saved sessions and workspaces. Reopen an entry from its archive to reestablish the link after reopening a saved session or changing the parent.

Source desktop validation passed UTF-8 BOM and UTF-16LE CRLF byte-exact exports, review cancellation, both sides, repeat apply, archive undo/redo, child focus/wrap, standalone disk saves, missing sides, stale reloads, source replacement, parent closure and saved-session isolation. Focused browser staging checks passed inactive-controller operation, byte cloning, stale/forged reference rejection, corrupt archive rejection and exact original disk-token restoration.
