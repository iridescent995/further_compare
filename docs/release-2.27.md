# Further Compare 2.27.0

File → Open Left/Right in External Editor now opens disk-backed inputs in binary, table, three-way text, picture, audio, archive and registry comparisons. It uses the existing system-default or configured editor preference. It opens the saved input, leaving unsaved comparison edits and generated results unchanged. Reopen an advanced input to read external changes; these views do not automatically reload.

Native file references belong to the current session and follow their input when sides are swapped or tabs are switched. Opening an invalid input leaves the previous input's reference intact. Saved session files contain embedded data rather than disk permissions: reopen their inputs from disk before launching externally. Extracted archive entries likewise require saving and opening a real file. Missing, replaced or redirected files require reopening. Left/right commands do not target the three-way base input.

Right-clicking the empty counterpart of a one-sided folder entry now opens the panel context menu. Existing selections remain intact, actions that require a real entry stay disabled, and dismissing the menu returns keyboard focus to the panel. Shift+F10 can reopen that menu.

Validation: all 205 unit tests passed. Native development tests passed for all seven advanced comparison types, left/right routing, swaps, tab isolation, saved-session token stripping, malformed request rejection, missing files, invalid input preservation, archive-entry rejection and unsaved binary edits. Existing editor execution/settings, advanced swap, folder-pair and context-menu regressions also passed. The advanced external-editor workflow passed in both final Mac packages. The packaged context-menu workflow also passed. Shell and folder Open As regressions passed. All three package versions and changed application files match the verified build, and ZIP integrity, download links, sizes and SHA-256 checks passed. Windows runtime verification remains pending on a Windows host.
