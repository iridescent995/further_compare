# Release 2.115.0 — FLAC audio comparison

Audio Compare accepts native FLAC alongside WAV and AIFF. File pickers, folder double-click and file-manager comparison routing recognize .flac. Sessions retain the original source bytes; audio reports include source container, rate, channels, precision and duration.

FLAC decoding preserves the source sample rate and supports mono/stereo 8-, 16- and 24-bit input with known frame counts within the existing 8-million-sample and 32 MB limits. A tiny known-sample stream calibrates the runtime decoder’s PCM normalization before decoded values are reconstructed and checked against exact source integer precision. Unsupported decoder precision or rate, inconsistent layout and invalid input produce explicit errors. Higher bit depths, multichannel audio, unknown-length streams and other compressed formats remain open; this does not add FLAC checksum/MD5 verification or media editing. The app and report explicitly disclose that FLAC checksums are not verified: native decoding rejects tested header corruption/truncation but can accept payload/footer corruption.

Audio loading is now asynchronous and guarded per side/session. Superseded loads cannot replace newer input, reset/restore suppress stale results and errors, invalid replacement preserves the existing input, and reports/playback wait for pending loads. Restore stages both sources before committing either.

Source verification: exact WAV/FLAC equivalence, changed samples, playback metadata, original-byte session save/restore, swap, invalid-file preservation and folder single/double-click routing pass. Existing WAV and AIFF desktop workflows pass. Browser asynchronous-load races pass. Native browser decoding also passes all 65,536 signed 16-bit values, 32,768 dispersed 24-bit values, 24 rate/channel/depth combinations, genuinely compressed constant subframes and truncated input rejection. The unit suite reports 921 passed and one Windows-only skip. Both Apple Silicon and Intel Mac packages pass the FLAC workflow, including checksum-disclosure assertions. All three platform ZIPs, renderer/native asset identity, download sizes/SHA-256 and Windows browser download pass. Windows runtime verification remains open.

Decoder design references: [Web Audio decoding and resampling](https://webaudio.github.io/web-audio-api/) and [FLAC format](https://www.xiph.org/flac/format.html).
