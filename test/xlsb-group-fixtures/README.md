The downloaded pinned bytes match the original fixture SHA-256 `490f0430a6bd44bdf697c7a41a898bce632ce2b775797c3b8c1517764c0900b3`. Upstream Apache license and notice are retained. Neither original nor derivative was generated by Further Compare's workbook parser.

`original-bug66682.xlsb` is deliberately still rejected by the supported input profile because it contains worksheet metadata record 0x31. **This is not evidence that the entire original workbook is supported.**

`derived-groups.xlsb` is an explicitly transformed qualification fixture:

1. Removed the one worksheet cell-metadata record 0x31 and `xl/metadata.bin`, with its workbook relationship and content-type declaration.
2. Removed `xl/worksheets/binaryIndex1.bin`, its relationship and content-type declaration, because removing a preceding record invalidates its byte offsets.
3. Renumbered the original custom number-format declaration from reserved ID43 to unused ID164, and changed its single XF reference accordingly. The format code bytes remain exact.
4. Repacked the ZIP. All other entry payloads remain exact. All eleven worksheet formula and shared/array group record bodies **and record headers** remain byte-for-byte original. External-link metadata and every original formula token remain intact; no external target was fetched, substituted or invented.

`derivation.json` records exact hashes. `test/xlsb-group-independent.test.cjs` verifies each transformation, unchanged payloads, original rejection and the qualified projection.

Independent application readback: LibreOfficeDev 26.8.0.0.alpha0 (`2c87e51eeaa2b413ff4ae097b2705eea1995d8e5`) loaded both original and derivative through the retained `ReadGroups.java` UNO harness, with explicit named `MacroExecMode.NEVER_EXECUTE` and `UpdateDocMode.NO_UPDATE` constants, hidden read-only documents and a separate temporary profile. Automatic calculation was disabled after load; no recalculation command was issued. Readbacks were exported to new XLSX paths. No original file was overwritten. The Java API classes came from official `org.libreoffice:libreoffice:24.2.7` and were kept outside the repository.

Both readbacks show identical formulas, caches and number-format codes. C3:C6 are genuine members of the shared group whose bounding range C3:C10 has holes. C9 is a separately owned genuine array `unknownFunction()` with a `#NAME?` result. Its unknown function definition is not qualified; the application correctly marks its expression unavailable. C8's missing external reference is likewise unavailable. Seven of nine expressions qualify; comparing this sheet to itself in formula mode is explicitly unavailable, never falsely equal. The original and derived independent readbacks agree on these cases. This proves genuine group framing and shared-member behavior; it does not claim supported evaluation or decoding of the unknown UDF array.
